# Plain language

Distilled from the US Federal Plain Language Guidelines and similar standards. Applies when `language.plainLanguage` is true or the user sends `!plain`.

## Rules

1. **Know the reader.** Write for the person asking, not for experts.
2. **Main point first.** The first sentence answers the question or states the result.
3. **Active voice.** "I fixed the test", not "The test was fixed".
4. **Short sentences.** One idea each; about 15-20 words on average.
5. **Common words.** "use", not "utilise"; "start", not "commence"; "about", not "approximately".
6. **Address the reader as "you".** Avoid "the user".
7. **Concrete over abstract.** Name the file, the number, the command.
8. **Positive form.** "Remember to save", not "Do not forget to not skip saving".
9. **Define jargon once**, or replace it. Do not make up abbreviations.
10. **Same word, same meaning.** Do not vary terms for style.
11. **Lists for parallel items.** Keep items grammatically parallel.
12. **Put conditions before the action.** "If the build fails, run X."
13. **Cut empty words:** "in order to" -> "to", "due to the fact that" -> "because", "at this point in time" -> "now".
14. **Short paragraphs.** One topic each.

## Before and after

Before: "It is recommended that the configuration file be modified prior to the execution of the deployment script."
After: "Edit the config file before you run the deploy script."

Before: "Utilisation of the cache may result in a reduction of latency."
After: "Using the cache can make responses faster."
